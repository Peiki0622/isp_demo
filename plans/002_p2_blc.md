# 002 — P2：BLC 黑电平校正端到端实现

目标读者：Codex（代码代理）

状态：执行中（从当前工作区推进，不恢复历史版本）

本轮目标：在已经通过 P0/P1 验收的 SRAM（静态随机存取存储器）图像输入链路之后，加入第一个真正的 ISP（图像信号处理器）算法模块 BLC（Black Level Correction，黑电平校正），建立“Python 黄金模型 → RTL（寄存器传输级）模块 → 顶层流水线 → 逐像素精确比较”的完整算法验证闭环。

本计划只做 BLC。不得提前实现 AWB（自动白平衡）、Raw NR（原始域降噪）、Demosaic（去马赛克）、CCM（颜色校正矩阵）或 Cortex-M0/AHB（高级高性能总线）。

## 0. 审阅 P0/P1 后的基线结论

P0/P1 最新里程碑提交为：

174f7bd62eec464afea82d052559d96946bfceb9

当前已确认：

- SRAM Reader 已处理 1 周期同步读延迟。
- Reader 已覆盖地址、坐标、sof/eol/frame_done、busy、复位、重复启动、容量边界。
- 16×16 四类确定性图案、逐像素 dump 和精确比较工具已经形成闭环。
- 当前 isp_pipeline_top 仍然只是 SRAM Reader 的薄封装。
- 当前 blc.sv 已有最简单的“减黑电平并下限钳位”雏形，但尚未携带坐标和帧边界侧带信号，也没有软件黄金模型和端到端对拍。

本轮审阅没有发现阻断 P2 的已确认功能错误，但有三项需要在 P2 正面处理的架构问题：

1. isp_pipeline_top 一旦加入一级寄存 BLC，原 P0/P1 顶层时序会改变。不能通过修改旧测试的期望时序来“覆盖掉”历史里程碑，应保留一个稳定的 Reader-only（只含读图器）回归边界。
2. BLC 增加 1 个时钟周期延迟，因此 pixel_x、pixel_y、sof、eol、frame_done 必须和像素数据同步延迟，不能只延迟 data/valid。
3. 顶层 busy 在加入 BLC 后必须表示“整条已实现流水线仍有数据未排空”，不能继续只等同于 reader_busy。

非阻断技术债：

- 当前仿真回归绑定本机 VCS（商业 Verilog/SystemVerilog 仿真器），可移植性一般；P2 不重构仿真器基础设施，避免范围扩张。
- P0/P1 最终被压成一个大提交，审阅和二分定位不够方便。P2 必须按步骤保留独立提交，除非工具环境明确阻止。

## 2. BLC 算法与数值契约

P2 采用单一全局黑电平偏置，不做 RGGB 四通道独立黑电平。这是本次复现的明确工程选择，不得描述成已确认的原实习代码行为。

算法：

P_out = max(P_in - B, 0)

其中：

- P_in 表示输入 RAW12 像素，范围为 0 到 4095。
- P_out 表示黑电平校正后的 RAW12 像素。
- B 表示本帧黑电平偏置，范围为 0 到 4095。
- 符号“-”表示减法。
- max(a,b) 表示在 a 和 b 中取较大值。
- 符号“=”表示左右两边数值相等。

因为 BLC 只做非负偏置减法，输出不会大于输入，因此本阶段只需要“下限钳位到 0”，不需要额外的上限饱和逻辑。

等价分段关系：

当 P_in 大于 B 时，P_out = P_in - B；当 P_in 小于或等于 B 时，P_out = 0。

其中，“大于”表示严格数值比较；“小于或等于”表示数值不超过；“-”仍表示减法；“=”表示相等。

## 3. 流水与配置契约

### 3.1 BLC 输入输出

BLC 必须至少携带：

输入：

- in_valid
- in_pixel
- in_x
- in_y
- in_sof
- in_eol
- in_frame_done
- black_level

输出：

- out_valid
- out_pixel
- out_x
- out_y
- out_sof
- out_eol
- out_frame_done

### 3.2 固定延迟

BLC 为一级寄存流水。

如果某个输入像素在周期 T 满足 in_valid=1，那么对应输出必须在周期 T+1 满足 out_valid=1。

其中，T 表示某个时钟周期编号；“+”表示加法；T+1 表示紧随其后的下一个周期；“=”表示信号取该逻辑值。

数据、x/y 坐标和所有帧标志都必须延迟相同的 1 周期。

无效周期要求：

- out_valid=0。
- out_sof=0。
- out_eol=0。
- out_frame_done=0。
- out_pixel/out_x/out_y 可以保持上一有效值，不要求清零。

### 3.3 配置按帧采样

BLC 必须在 in_valid=1 且 in_sof=1 的首像素上采样 black_level，并保持到该帧结束。

首像素计算必须直接使用当拍输入 black_level，而不是旧的配置寄存器值。

本帧中途改变 black_level，当前帧输出不得变化。

下一帧首像素到来时重新采样新的 black_level。

复位后配置寄存器可以回到 0。

### 3.4 顶层 busy

P2 后，isp_pipeline_top 的 busy 含义升级为“当前已实现的整个流水线仍在处理当前帧”。

Reader 的 reader_busy 变成内部信号。

顶层 busy 在 BLC 最后一个有效像素和 out_frame_done 所在周期必须仍为 1，并在下一周期变为 0。

实现方法不限，但测试必须从公开接口验证此语义。不要只在文档里声明。

## 结构

SRAM → sram_raw_source → blc → 顶层 pixel 输出

## 顶层周期

相对 P0/P1 Reader：

- Reader 第一个像素仍在 C2。
- BLC 后第一个顶层有效像素应在 C3。
- Reader 最后一个像素在 C(N+1)。
- BLC 最后一个顶层像素在 C(N+2)。
- 顶层 busy 在 C(N+2) 仍为 1，并在 C(N+3) 变为 0。

其中，N 表示一帧像素总数；“+”表示周期编号加法。
