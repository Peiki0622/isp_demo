# 005 — P5：CCM 颜色校正矩阵的有符号定点流水

目标读者：Codex（代码代理）

状态：已完成

本轮目标：在已经通过 P0/P1、P2、P3、P4 验收的 SRAM → Reader → BLC → AWB Gain → Bilinear Demosaic → RGB12 链路之后，加入 CCM（Color Correction Matrix，颜色校正矩阵），完成第一个真正的 RGB 域 3×3 有符号矩阵乘加模块。

本轮学习重点：

- RGB 三通道并行数据路径；
- 9 个有符号固定点系数；
- 无符号像素与有符号系数乘法；
- 乘积位宽与三项累加位宽；
- 负值下限钳位与高亮上限饱和；
- 正数 round-half-up（四舍五入）；
- 两级流水保持 1 pixel/cycle 吞吐；
- 9 个系数的帧级原子采样；
- 保存 P4 Demosaic-only 历史回归边界；
- Python 全链黄金模型与 RGB36 精确对拍。

本轮不实现 Gamma、CSC（颜色空间转换）、YCbCr、Raw NR、Chroma NR、Hue、LCC、EE 或 Cortex-M0/AHB。

## 2. 系数固定点契约

P5 不使用含糊的“Q3.12/Q4.12”命名作为唯一规范，而是直接冻结比特语义：

- coefficient width = 16 bit
- signed two's-complement（二进制补码）
- fractional bits = 12

真实系数与编码关系：

coef_real = coef_code / 4096

其中，coef_real 表示数学意义上的实数矩阵系数；coef_code 表示 16 位有符号补码整数；4096 等于 2 的 12 次幂，是固定点缩放因子；“/”表示除法；“=”表示两边定义为相同的系数值。

示例：

- 0 → 0.0
- 2048 → +0.5
- 4096 → +1.0
- 6144 → +1.5
- -2048 → -0.5
- -4096 → -1.0
- -32768 → -8.0
- 32767 → 约 +7.999755859375

配置和 golden 文件之间禁止用 float 作为正式交换格式。

## 3. CCM 数学契约

输入像素：

R_in、G_in、B_in ∈ [0,4095]

其中，R_in、G_in、B_in 分别表示 Demosaic 输出的 12 位红、绿、蓝通道；“∈”表示属于给定范围。

九个系数：

c00 c01 c02
c10 c11 c12
c20 c21 c22

先在整数编码域计算：

A_R = R_in × c00 + G_in × c01 + B_in × c02

其中，A_R 表示红色输出通道的未缩放有符号累加值；R_in/G_in/B_in 表示输入三通道；c00/c01/c02 表示第一行有符号固定点系数编码；“×”表示整数乘法；“+”表示有符号整数加法；“=”表示右侧定义 A_R。

A_G = R_in × c10 + G_in × c11 + B_in × c12

其中，A_G 表示绿色输出通道的未缩放有符号累加值；c10/c11/c12 表示第二行系数；其他符号含义与 A_R 相同。

A_B = R_in × c20 + G_in × c21 + B_in × c22

其中，A_B 表示蓝色输出通道的未缩放有符号累加值；c20/c21/c22 表示第三行系数；其他符号含义与前两式相同。

### 3.1 输出钳位与舍入

对任意一个通道累加值 A：

如果 A <= 0：

P_out = 0

其中，A 表示该通道的 signed 累加值；P_out 表示该通道最终 RGB12 输出；“<=”表示小于或等于；“=”表示输出值定义。

如果 A > 0，先：

S = (A + 2048) >>> 12

其中，S 表示去掉 12 个固定点小数位后的正整数；2048 是半个固定点 LSB 对应的舍入偏置；“+”表示加法；“>>> 12”表示右移 12 位；因为 A 在这个分支为正数，算术右移与逻辑右移数值结果一致；“=”表示结果定义。

最终：

P_out = min(S,4095)

其中，P_out 表示最终 RGB12 通道；S 表示舍入后的正整数；min(a,b) 表示取两者较小值；4095 是 12 位无符号最大值；“=”表示结果定义。

P5 不对负累加做“对称舍入后再裁剪”，因为所有 A<=0 最终都明确钳位到 0。

## 4. 位宽契约

输入 RGB12 为无符号 0..4095。

在乘法前，将每个输入显式扩展成 13 位 signed 正数：

{1'b0, pixel[11:0]}

16 位系数为 signed。

建议每个乘积至少使用 29 位 signed 保存。

三个 signed 乘积相加时全部先 sign-extend 到至少 31 位 signed accumulator。

P5 不要求把理论最小位宽抠到极限；优先保证无溢出、符号传播明确和代码易审阅。

任何以下写法都视为错误：

- 先把 signed product 截成 16 位；
- 把 RGB12 直接 cast 成 12 位 signed，导致 2048..4095 被解释为负数；
- 三项各自在窄位宽中相加后再赋给宽 accumulator；
- 在完成负值判断和上限比较前就截成 RGB12。

## 5. 两级流水契约

### Stage 1 — Multiply

输入有效拍 T：

- 判定该像素是否为 sof；
- 如果 valid+sof，9 个 effective coefficients 使用当前外部矩阵，并同时锁存到 frame matrix registers；
- 否则使用当前帧锁存矩阵；
- 计算并寄存 9 个 signed products；
- 同时寄存 x/y/sof/eol/frame_done；
- stage1_valid 注册。

### Stage 2 — Accumulate / Round / Clamp

下一个周期：

- 三组各 3 个 Stage-1 product 做 signed 宽位累加；
- 对每通道执行负值钳位、+2048、右移 12、4095 饱和；
- 注册 out_r/out_g/out_b；
- x/y/flags 再延迟一级；
- out_valid 注册。

因此 CCM 从输入到输出固定延迟 2 个时钟周期，但稳态吞吐仍为 1 pixel/cycle。

禁止 identity matrix 走零延迟旁路。

## 6. 帧配置契约

外部接口提供 9 个 signed 16-bit coefficient ports：

c00..c22

全部只在：

in_valid && in_sof

同一个时钟沿原子采样。

第一像素必须直接使用当拍外部新矩阵。

当前帧中途修改任意系数，当前帧不得变化。

下一帧有效 sof 时同时更新全部 9 个系数。

reset 后 frame matrix 必须为 identity：

4096   0      0
0      4096   0
0      0      4096

这样非规范的非-sof 输入也至少保持颜色不变；正式帧仍以 sof 配置为准。

## 9. 重点易错项（均已检查并排除）

- [x] 把 RGB12 直接解释成 signed 12-bit，2048..4095 变负数。
- [x] signed coefficient 和 unsigned pixel 混合表达式导致 SystemVerilog 隐式无符号扩展。
- [x] 9 个 product 中某几个没有完整保留符号/位宽。
- [x] 三项 accumulator 在窄位宽加完以后才扩宽。
- [x] 负 accumulator 先加 rounding bias 再判断，造成语义模糊。
- [x] 正 accumulator 舍入后超过 4095 却截断回绕。
- [x] matrix 在 frame 中途被外部变化污染。
- [x] 第一像素使用上一帧 matrix。
- [x] matrix 行列转置；使用非对称矩阵而非只用对称的 R/B swap 排除该错误。
- [x] identity matrix 被做成零延迟 bypass，破坏固定两级流水。
- [x] x/y/flags 只延迟一级或三级，与 RGB 两级错拍。
- [x] P4 旧 top 测试被直接加两拍，而没有保存 Demosaic-only 边界。
- [x] top busy 忽略 Stage-1 product 或最后 out_valid drain。
- [x] Python 用 float matrix，RTL 用 fixed-point，边界无法 bit-exact。
- [x] config 保留 1.0/0.0 浮点而与正式寄存器编码不一致。
